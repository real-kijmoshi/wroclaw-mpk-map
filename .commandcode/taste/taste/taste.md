# Taste
- Wants UI to look modern and native to the current Apple/iOS design language (e.g. "Liquid Glass", glassmorphism, latest platform APIs); explicitly dislikes generic "AI-made" or template-looking UIs. Confidence: 0.9
- Cares deeply about visual polish and pixel-perfect details — repeatedly asks to "polish", fix spacing/cut-off elements (e.g. clipped indicators), and remake modals/screens from scratch until they look clean and spotless. Confidence: 0.9
- Prefers left-aligned (start-aligned) wrapping grid/flex layouts — when items don't fill a complete row, they should run left (`flex-start`) rather than being centered; centering creates unwanted right-side margins and "weird centering at bottom" on partial rows. Confidence: 0.85
- Prefers interactive element sizes (e.g. grid chips) to be derived from actual available width rather than forcing a fixed minimum column count, so that small screens don't squeeze touch targets below the 44pt/48px minimum — verifies sizing across real device widths (320px, 375px, 430px, etc.). Confidence: 0.8
- Prefers grid layouts (e.g. badge/chip grids) to be capped at a maximum of 6 columns/items per row — chips still derive their size from available width on small screens (fewer columns when 6 wouldn't fit), but on wider screens the count is capped so the layout doesn't sprawl. Confidence: 0.8
- Prefers map markers that are color-coded by vehicle type (e.g. buses red, trams blue, night buses dark blue, temporary buses green), square with slightly rounded corners, showing direction via a small arrow while keeping text unrotated, and centered on the vehicle's actual position. Confidence: 0.8
- Prefers selecting an item on the map not to disrupt the view (no automatic zoom/pan); if behavior is debatable, prefers exposing it as a user setting. Confidence: 0.6
- Prefers keeping code for a feature in place but disabling it (with an option to re-enable later) rather than deleting it, when the feature is not currently wanted. Confidence: 0.7
- Prefers native map rendering (react-native-maps) over web-based map libraries in the mobile app ("dont use web maps"). Confidence: 0.8
- Prefers the Expo workflow and latest Expo SDKs over native Xcode tooling (Xcode is not usable on their machine). Confidence: 0.7
- Cares about app performance — proactively asks for optimization so the app runs smoother and loads faster. Confidence: 0.6
- Strict TypeScript: never uses `any` or disables type checks (`# type: ignore`, `eslint-disable`) to make removed-or-refactored code compile — removal work must keep type safety intact. Confidence: 0.9
- Validates app changes through the project's full gate — `npm run lint`, typecheck (`tsc --noEmit`), and `expo export`/`build` — treating all three as required before the change is considered done. Confidence: 0.85
- Explores the existing project structure (AGENTS.md invariants, constants, hooks, themed components, color-scheme hook, settings, and design brief) before writing any new code rather than jumping straight to implementation. Confidence: 0.85
- Verifies frontend changes end-to-end through browser automation (`npx agent-browser`): opens the served page, captures screenshots, inspects interactive element refs via `snapshot`, clicks controls, and re-screenshots to confirm behavior/state changes — often reviewing the rendered output with a Vision model (e.g. confirming an accent color actually switched). Confidence: 0.9
- When verifying a feature that persists user choices, explicitly tests state survival across a full page reload (open → set → screenshot → reload → re-screenshot → compare) rather than only confirming the value is set within a single session. Confidence: 0.85
- When a change exposes a shared value (e.g. `theme.accent`) to multiple consumers, verifies that *all* consumers pick it up — not just the primary picker — by checking each distinct usage site (e.g. both the settings checkmark and link text on an error state). Confidence: 0.8
- When re-running a verification pass, forces a clean rebuild (e.g. `expo export --clear` and `rm -rf` of prior export dirs) rather than trusting incremental/cached output, so a "recheck" is genuinely independent. Confidence: 0.75

### App architecture & data flow
- Prefers `useSyncExternalStore`-based external stores (mirroring the existing `selection`/`preferences` stores) for state shared across screens or components, and one-shot "consume" semantics for inter-screen handoffs (e.g. search → map) instead of serializing payloads through Expo Router query parameters. Confidence: 0.85
- Validates API responses field-by-field before use — type-checks that the payload is an object, that array/object fields are the expected shape, that ids/names are strings, and that lat/lon are finite numbers — and never blindly casts unknown JSON into typed models. Confidence: 0.85
- Uses `AbortController` for debounced network requests, aborting the previous in-flight request whenever the query changes so a slow/stale response can never overwrite newer results (and aborting on effect cleanup/mount). Confidence: 0.85
- When correctness-critical logic has no test runner and cannot add new dependencies, writes a throwaway validation script (e.g. in a scratchpad) that asserts the algorithm's concrete invariants, rather than skipping validation. Confidence: 0.7
- Uses line/block-scoped `eslint-disable` comments with an explanatory reason when a lint rule flags *correct* code (e.g. reacting to an external store in an effect, or idempotent caching via a ref inside a `useMemo`) — distinct from disabling checks to make code compile, which is never done. Confidence: 0.7
- When adding UI, reuses the project's existing components and matching conventions (e.g. `Choice`/`Divider`/`Section` and `View`-key-wrapped list items) rather than introducing fragments, shorthand `<>`, or new UI primitives. Confidence: 0.8
- Does not misrepresent HTTP cache freshness in the UI: a map payload whose ETag/timestamp persists across 304 revalidation responses must not be presented as "time since the latest successful poll"; avoids forcing server-side cache invalidation or adding per-second rerender timers purely to update a cosmetic freshness timestamp. Confidence: 0.8
- On first app launch, defaults to a limited subset of data (e.g. trams only) rather than loading everything, to avoid initial-render lag from too many vehicles — but only on first launch; subsequent launches restore the persisted user filter and never re-apply a startup default. Confidence: 0.9
- Distinguishes first-launch (no stored selection exists → apply default) from an explicitly user-cleared filter (stored but empty → respect the choice); startup defaults must never override an explicit user empty/cleared state. Confidence: 0.8
